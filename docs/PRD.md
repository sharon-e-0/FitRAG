# FitRAG PRD

## 1. 제품 개요

FitRAG는 사용자의 식사 기록, 음식 이미지, 감정 상태, 상황 정보, 체중 예측, RAG 기반 건강 코칭을 통합하는 AI 건강 관리 웹 애플리케이션이다.

현재 구현된 제품 범위는 다음과 같다.

- Google OAuth 기반 로그인
- 식사 텍스트 기록
- 식사 이미지 업로드
- Gemini 기반 음식 영양 분석
- Gemini 실패 시 fallback 영양 추정
- 식사별 감정/상황 태그 저장
- Supabase PostgreSQL 저장
- RAG 문서 생성 및 pgvector 검색 구조
- AI 건강 코치 채팅
- RAG 임베딩 상태 진단
- 체중 예측 화면
- Dashboard 요약 화면

## 2. 목표

사용자가 식사 기록을 남기면 자동으로 칼로리와 주요 영양소를 계산하고, 누적 식사 데이터를 기반으로 개인화된 건강 코칭과 체중 변화 예측을 제공한다.

## 3. 주요 사용자

- 식사 기록을 간단히 남기고 싶은 사용자
- 감정과 식습관의 관계를 보고 싶은 사용자
- 체중 변화 방향을 예측하고 싶은 사용자
- 개인 식사 기록 기반 AI 코칭을 받고 싶은 사용자

## 4. 핵심 사용자 시나리오

### 4.1 로그인

1. 사용자는 로그인 페이지에서 Google OAuth 로그인을 클릭한다.
2. Supabase Auth를 통해 인증한다.
3. 인증 성공 후 보호된 페이지에 접근한다.

### 4.2 식사 저장

1. 사용자는 `/meals/new`에서 식사 유형, 시간, 감정, 상황을 선택한다.
2. 음식 설명을 텍스트로 입력하거나 JPEG/PNG/WEBP 이미지를 업로드한다.
3. `Save meal`을 클릭한다.
4. 시스템은 Gemini 음식 분석을 먼저 시도한다.
5. Gemini 분석 성공 시 결과를 저장한다.
6. Gemini 분석 실패 시 fallback 추정값으로 저장한다.
7. 식사 기록과 영양 분석 결과를 Supabase에 저장한다.
8. 저장된 식사는 Dashboard에 표시된다.

### 4.3 음식 분석

사용자는 `Analyze meal` 버튼으로 저장 전 영양 분석 결과를 미리 볼 수 있다.

분석 결과:

- 음식명
- 칼로리
- 탄수화물
- 단백질
- 지방
- 당
- 나트륨

### 4.4 Dashboard 확인

Dashboard에서 사용자는 다음 정보를 확인한다.

- 저장된 식사 목록
- 분석된 칼로리
- RAG 임베딩 상태
- 칼로리 요약 차트
- 영양소 차트
- 체중 예측 그래프
- 감정 분석 리포트
- AI 코치 채팅 UI

### 4.5 RAG 건강 코치

1. 사용자는 `/coach`에서 질문을 입력한다.
2. 시스템은 질문 임베딩을 생성한다.
3. pgvector에서 관련 문서를 검색한다.
4. 검색 결과를 Gemini 프롬프트에 포함한다.
5. Gemini가 답변을 생성한다.
6. 검색 결과가 없거나 실패하면 최근 식사 기록 fallback을 사용한다.

### 4.6 체중 예측

사용자는 `/prediction`에서 체중, 키, 나이, 활동량, 섭취 칼로리, 운동 칼로리를 입력한다.

시스템은 다음을 계산한다.

- BMR
- TDEE
- 일일 에너지 수지
- 7일 예측 체중
- 30일 예측 체중
- 목표 체중 도달 예상일

## 5. 기능 요구사항

### 5.1 인증

- Google OAuth 로그인을 제공해야 한다.
- 로그인 세션을 유지해야 한다.
- 보호 페이지 접근 시 미인증 사용자는 로그인 페이지로 이동해야 한다.
- 로그아웃을 제공해야 한다.

### 5.2 식사 기록

- 식사 유형을 선택할 수 있어야 한다.
- 식사 시간을 입력할 수 있어야 한다.
- 감정 상태를 선택할 수 있어야 한다.
- 상황 태그를 선택할 수 있어야 한다.
- 텍스트 식사 기록을 입력할 수 있어야 한다.
- JPEG/PNG/WEBP 식사 이미지를 업로드할 수 있어야 한다.
- 식사 저장 시 자동으로 영양 분석이 실행되어야 한다.

### 5.3 음식 분석

- Gemini 2.5 Flash로 음식 분석을 시도해야 한다.
- 이미지 또는 텍스트 기반 분석을 지원해야 한다.
- Gemini 실패 시 fallback 추정값으로 저장 흐름을 유지해야 한다.
- fallback 결과는 `estimated`로 표시해야 한다.

### 5.4 RAG

- 식사 기록을 자연어 문서로 변환해야 한다.
- 문서에는 날짜, 식사 유형, 음식명, 칼로리, 탄수화물, 단백질, 지방, 감정, 상황, 메모를 포함해야 한다.
- 문서를 text-embedding-004로 임베딩해야 한다.
- pgvector에 저장해야 한다.
- 유사도 검색 API를 제공해야 한다.
- 코치 답변 생성 시 검색 문서를 컨텍스트로 사용해야 한다.

### 5.5 Dashboard

- 저장된 식사 기록을 조회해야 한다.
- 분석 결과가 있으면 칼로리를 표시해야 한다.
- 분석 결과가 없으면 `Pending analysis`를 표시해야 한다.
- RAG 임베딩 진단 정보를 표시해야 한다.

### 5.6 체중 예측

- BMR/TDEE 기반 예측을 제공해야 한다.
- 7일/30일 예측을 제공해야 한다.
- 목표 체중 도달일을 계산해야 한다.

## 6. 비기능 요구사항

- Next.js 14 App Router를 사용한다.
- TypeScript를 사용한다.
- TailwindCSS와 shadcn 스타일 컴포넌트를 사용한다.
- Supabase PostgreSQL을 사용한다.
- pgvector를 사용한다.
- AI API 실패 시 사용자가 기능을 계속 사용할 수 있어야 한다.
- 인증이 필요한 API는 Supabase 세션을 검증해야 한다.

## 7. 현재 제한사항

- 이미지 원본은 아직 Supabase Storage에 영구 저장하지 않는다.
- 현재 이미지 분석 업로드 지원 형식은 JPEG/PNG/WEBP이다.
- HEIC/HEIF는 브라우저 또는 외부 도구로 변환 후 업로드해야 한다.
- Health Connect SDK 실제 연동은 아직 UI/DB 설계 중심이며 실기기 동기화는 미구현이다.
- Dashboard 일부 차트는 샘플 데이터 기반이다.
- Gemini 실패 시 fallback 추정값은 정확한 AI 분석이 아니라 보수적 추정값이다.

## 8. 성공 기준

- 사용자가 Google 로그인 후 Dashboard에 접근할 수 있다.
- 사용자가 텍스트 식사 기록을 저장할 수 있다.
- 사용자가 이미지 식사 기록을 저장할 수 있다.
- 저장 시 칼로리/영양소가 자동 계산되어 DB에 저장된다.
- Dashboard에서 저장된 식사와 칼로리를 볼 수 있다.
- RAG 상태 진단 API가 동작한다.
- 체중 예측 화면이 정상 계산된다.
